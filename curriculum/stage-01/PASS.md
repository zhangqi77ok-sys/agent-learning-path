# Stage 01 过关题作答

## 1. 为什么用环境变量而不是写死 Key？

- **防泄漏**：代码进 Git / 截图 / 日志时，硬编码 Key 几乎必然扩散；环境变量 + `.gitignore` 的 `.env` 把密钥留在运行环境。
- **可轮换**：中转站/官方 Key 失效或泄漏时，只改环境，不用改代码、不用重新发版。
- **多环境**：本地 / CI / 演示机用不同 Key 与 `base_url`，同一套代码可切换。
- **面试口径**：和 Java 里把 DB 密码放配置中心/环境、而不是写进 `application.yml` 提交仓库是同一纪律。

## 2. 中转站和官方 API 在客户端配置上差什么？

| 项 | 官方（如 OpenAI / DeepSeek） | 第三方中转站 |
|----|------------------------------|--------------|
| `base_url` | 厂商固定域名 | 中转站提供的 `/v1`（或厂商兼容路径） |
| `api_key` | 厂商控制台签发 | 中转站账号 Token；权限与计费以中转为准 |
| `model` | 官方模型名 | **以中转站挂名为准**，可能和官方同名不同后端 |
| 协议细节 | 通常完整兼容 | 多数兼容 Chat Completions；少数会拦通用客户端 / 只放行特定 UA |
| 排障 | 看厂商错误码 | 先确认是鉴权、模型名，还是中转 WAF/兼容性 |

客户端代码形态相同（`OpenAI(api_key=..., base_url=...)`），差的是 **三件套配置与兼容性预期**，不是另一套 SDK。
