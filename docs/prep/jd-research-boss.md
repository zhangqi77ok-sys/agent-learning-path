# Boss / 猎聘向：Agent 应用工程师 JD 调研摘要

> 用途：驱动 `docs/curriculum-foundations.md` 的教学目标与验收口径。  
> 来源：公开岗位描述的共性归纳（Boss 直聘 / 猎聘等「AI Agent / 智能体 / 大模型应用」岗），非私有数据抓取。

## 岗位画像（大小厂共性）

| 维度 | 高频要求 |
|------|----------|
| 语言与后端 | Python 为主；FastAPI/Flask；可接受 Go/Java 作为业务侧 |
| Agent 内核 | Tool Calling、记忆、工作流编排、Multi-Agent |
| 框架 | LangChain / LangGraph / Dify / AutoGen / CrewAI（至少一种有落地） |
| 知识层 | RAG、向量库、重排、企业知识库对接 |
| 协议与集成 | MCP、第三方 API、内部业务系统对接 |
| 工程化 | Docker（常考）、部分要求 K8s；CI/CD；私有化部署 |
| 生产意识 | 性能与成本、可观测、评测与迭代、安全合规 |

## 常见职责关键词

- 任务规划 / 工具调用 / 记忆管理 / 多 Agent 协同
- RAG 检索链路优化（召回、重排、缓存）
- 从 Demo 到生产：API 封装、鉴权、稳定交付
- 与业务系统（Jira / 飞书 / 内部 API）集成

## 面试官真正在筛的三件事

1. **能不能讲清边界**：工具权限、数据权限、失败怎么重试  
2. **能不能讲清编排**：为什么用图/状态机，而不是单轮 chat  
3. **能不能讲清效果**：有没有可复现评测（成功率 / 延迟 / 成本）

## 对候选人作品集的隐含要求

能演示一条端到端链路：用户问题 → 鉴权 → 检索/工具 → 回答带引用 → Trace 可查 → 指标可报。
